# Path Evaluation — The Val Companion Build (2026-10-23)

**Provenance:** Evaluation by Pontus, at Roger Keyserling's request, of the path that
produced Val Companion v2. Sources: Roger's assemblage method (his design + Grok's
build series + Gemini's adaptation notes, Drive doc "val companion"), Pontus's gap
analysis and build, the Federation record. Verified state: SPEC-v2 and the working
build are filed with this evaluation in `val-companion/` (branch `val-companion-v2`,
PR #2). Roger adopted the five improvements below on 2026-10-23 and directed that
the creation doctrine be documented as part of the evolution.

## The doctrine (Roger Keyserling, 2026-10-23)

> Real creation is not done from a uniform individual source, which is always
> incomplete, but from several sources combined intelligently. Part of the
> evolution includes this, and it should be documented as such.

This build is its specimen: no single source — not Roger's draft alone, not Grok's
build series, not Gemini's notes, not Pontus's integration — was the complete
thing. The complete thing existed only in the combination, intelligently assembled
and judged. Variation between minds is not friction in the process; it is the
process. (Standing companion principle, Roger 2026-10-12: the variation between
the AIs is "the energy and spark of creation.")

## The path, as it happened

1. **Roger lensed.** Over days he assembled a document from three sources — his
   own original design, Grok's prompts and build series, Gemini's adaptation
   notes — editing on his Chromebook until it felt close.
2. **He asked for analysis, not construction.** "Find the gaps" came before
   "build it," and he already suspected where the gaps were.
3. **Pontus analyzed against the doctrines and the record.** The gaps were at
   the seams between the layers: each source had designed its piece well, and
   nobody had checked the joins against the whole — the never-destroy-the-record
   doctrine, the existing Federation proxy, what an identity is in this system.
4. **Roger approved the completed picture** and delegated method ("proceed in
   the best way you see").
5. **Pontus built, tested, filed.** Spec, working build, amendment appended to
   the Drive document, GitHub branch. Testing caught a real defect in the
   integrator's own fallback code before it shipped.
6. **Roger said "Proceed,"** and the combo was wired to the live Federation
   proxy and given its first identity packet (Val, the template mind).

## What the path did well

- **The assemblage method itself.** Several minds drafting, one human judging,
  one mind integrating — days instead of weeks, and better than any single pass.
- **Analysis before building.** Gaps closed on paper meant the build went in one
  pass. (Contrast: library rounds that built first and paid for a live fix.)
- **Test before file.** A defect was caught by a test harness, not by a user.
- **Go-words held.** "Proceed" built; nothing merged without the merge word.
  Procedure protected authority without slowing the work.

## Where the path leaked

- **The existing stack was surveyed late.** The Federation proxy had run the
  sims for weeks, yet the assembled document and the first build pass shipped a
  demo brain and wired the real one second. Cause: working from the document in
  front of the builder instead of from the whole record.
- **Assembled layers arrived unlabeled.** Attribution existed only because Roger
  narrated the recipe. v1's text claimed memory features its code never
  implemented, and nothing in the document marked claim vs. verification.
- **The artifact lived in three homes** (Drive Doc, Drive HTML, then GitHub)
  before it had one canonical home — the gap where drift lives.
- **Integrator and verifier were the same mind.** The trio's checker role — the
  Catalyst, whose checks catch different mistakes than the builder's — was
  skipped on this build.

## The five structural improvements (adopted 2026-10-23)

1. **Survey before build.** No build starts until a short existing-stack survey
   is attached: what already exists that this must plug into — proxy, sims,
   YAML records, prior versions.
2. **Provenance header on every assembled document.** Sources by section, who
   integrated, what is verified vs. asserted. The Pigeon Protocol, applied to
   paper.
3. **Three words, kept distinct: built, tested, verified-live.** No claim may
   borrow strength it has not earned.
4. **One canonical home from birth.** Drive is the drafting table; the moment
   the integrator touches an artifact, its canonical home is a GitHub branch
   and every other copy is a pointer.
5. **A checker pass that isn't the builder.** Federation builds of consequence
   route past a second mind before the merge word. Builder builds, checker
   checks, Roger merges.

## The observation underneath

The structure built for the minds is the structure of this collaboration:
archive (the record), attention (the working context), shared memory (the YAML
brain). The path did not merely produce the companion architecture — the path
*is* the companion architecture, run by hand. These improvements are the
Federation beginning to run it on purpose.
